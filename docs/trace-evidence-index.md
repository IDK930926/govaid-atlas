### `TRACE-B` — Dynamic Missing-Field Detection, Input Validation & Stateful Resume
- **File Path:** `artifacts/traces/trace-b-missing-field-resume.json`
- **Run ID:** `trace-b-missing-field-resume`
- **Scenario:** Applicant queries `"我想查詢租屋補助，但尚未填寫月所得"` with `monthlyIncome: null` included in `requiredFields`.
- **Key Agent Decision:** Agent detects missing `monthlyIncome` (`selectedTool: "request_missing_field"`), pauses at `WAITING_FOR_HUMAN`, and asks the field-specific question `"請問您的家庭平均月所得約是多少？"`.
- **Validation:**
  1. First user input `"not-a-number"` is rejected by `validateMissingFieldInput` (`valid: false`, `errorCode: "INVALID_MONTHLY_INCOME"`), keeping the run safely paused at `WAITING_FOR_HUMAN`.
  2. Second user input `28000` is validated (`valid: true`, `value: 28000`).
- **Tool Execution:** `request_missing_field` → `humanGate` state transition (`beforeState.monthlyIncomeProvided: false` → `afterState.monthlyIncomeProvided: true`, `nextPlannerAction: "evaluate_central_rules"`) → `evaluate_central_rules` → `evaluate_actual_scenario` → `evaluate_what_if_scenario` → `get_policy_evidence` → `complete`.
- **Final State:** `finalStatus: "COMPLETED"`, `finalEligibilityStatus: "PARTIAL_CHECK"`.
- **Why the Trace Matters to the Competition:** Demonstrates stateful multi-turn Human-in-the-Loop governance: the Agent asks dynamic field-specific questions, rejects malformed user input with a full audit trail, updates structured state upon valid input, and resumes without losing context.
